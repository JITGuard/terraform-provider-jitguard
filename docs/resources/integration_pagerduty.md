# jitguard_integration_pagerduty (Resource)

Manages the PagerDuty integration. PagerDuty is the only integration the
machine API can manage; Slack is installed through OAuth in the JIT Guard web
app and is read-only in Terraform.

## Write-only API key

`api_key` is write-only: Terraform sends it on apply but never stores it in
state or plan. Because Terraform cannot compare a write-only value, change
`api_key_version` when you rotate the key so Terraform re-sends it:

```terraform
resource "jitguard_integration_pagerduty" "this" {
  api_key         = var.pagerduty_api_key
  api_key_version = 2
}
```

The API validates the key against PagerDuty before storing it. A key without
read-only access to on-call schedules is rejected.

Deleting the resource disconnects PagerDuty.

## Example Usage

```terraform
variable "pagerduty_api_key" {
  type      = string
  sensitive = true
}

resource "jitguard_integration_pagerduty" "this" {
  api_key         = var.pagerduty_api_key
  api_key_version = 1
}
```

- `masked_api_key` (String) The server-side masked key (e.g. ****1234). Never the full key.



## Import

```terraform
terraform import jitguard_integration_pagerduty.this pagerduty
```

Import adopts an existing connection and reads `connected` and
`masked_api_key`. The write-only `api_key` cannot be recovered from the API;
configure it for subsequent applies.
