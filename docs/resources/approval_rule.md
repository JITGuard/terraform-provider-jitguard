# jitguard_approval_rule (Resource)

An approval rule. Create, read, update, and delete via the API-key-secured
JIT Guard machine API. Updates are full replacements guarded by an
`If-Match`/ETag; a concurrent edit on the server fails the apply with a 412.

## Example Usage

```terraform
resource "jitguard_approval_rule" "sre_emergency" {
  name          = "SRE Emergency"
  description   = "Emergency access for on-call SRE."
  auto_approve  = true
  enabled       = true
  sso_group_ids = ["grp-sre"]

  accounts {
    type       = "account_id"
    account_id = "111111111111"
  }

  permission_sets {
    type = "permission_set_arn"
    arn  = "arn:aws:sso:::permissionSet/ssoins-1111111111111111/ps-22222222222222222222222222222222"
  }
}
```

## Validation notes

- `name` is required; the schema does not impose a length limit.
- `auto_approve` is required: `true` (grant immediately) or `false` (require
  approval).
- `sso_group_ids` is required, but the schema does not require it to contain
  at least one group.
- `accounts` and `permission_sets` are optional nested blocks; neither is
  required to be present or non-empty.
- When `auto_approve = false`, `approver_group_ids` must be provided and
  non-empty. The provider validates this before making an API call.
- Account conditions match by AWS account ID (`account_id`), OU ID
  (`ou_id`), or tag; permission-set conditions match by SSO permission set
  ARN (`arn`, or `"*"` for any) or tag. `account_id`, `ou_id`, and `arn` are
  shape-validated when set.
- Each `type` must be one of the accepted values (`account_id`,
  `account_tag`, `ou_descendant` for accounts; `permission_set_arn`,
  `permission_set_tag` for permission sets). The provider does not enforce
  that a block's type-specific field is present; the API returns a precise
  400 `{ error, field }` for an incomplete condition.
